# Architecture Document: Cloudflare R2 Artifact Migration

## 1. Problem Statement
The Code Analysis Dashboard currently orchestrates over 15 parallel security scanners (SAST, AI agents, SCA, etc.). 
Each scanner produces distinct reporting evidence (e.g., `.sarif` files, `.json` logs, and SQLite databases). 

Currently, the orchestration relies on GitHub Actions' native artifact system (`actions/upload-artifact` and `actions/download-artifact`). This introduces three critical bottlenecks:
1. **Storage Limits:** GitHub's free tier caps artifact storage at 500MB per private repository. 15+ scanners easily exceed this limit, causing pipeline failures.
2. **Execution Latency:** GitHub compresses artifacts into `.zip` files during upload and decompresses them during download. This I/O overhead wastes billable execution minutes.
3. **Pagination Overhead:** The orchestrator (`source_identity.py`) must paginate through the GitHub REST API to locate and download dozens of separate artifact ZIPs, which is prone to rate-limiting and network latency.

## 2. Proposed Architecture (Hybrid Artifact Storage)
To eliminate these bottlenecks, we will migrate the temporary artifact brokering layer to **Cloudflare R2**, while keeping the CI/CD orchestration on GitHub Actions.

Cloudflare R2 provides a generous 10GB free tier, zero egress fees, and full AWS S3 API compatibility. 

### 2.1 Workflow Generation Changes (`generate_source_workflow.py`)
Instead of emitting `actions/upload-artifact` steps, the workflow generator will inject native AWS CLI commands into the parallel runner jobs.

**Old Flow:**
```yaml
- uses: actions/upload-artifact@v4
  with:
    name: scanner-output
    path: results.sarif
```

**New Flow (R2 Broker):**
```yaml
- name: Upload scanner-output to Cloudflare R2
  env:
    AWS_ACCESS_KEY_ID: ${{ secrets.R2_ACCESS_KEY }}
    AWS_SECRET_ACCESS_KEY: ${{ secrets.R2_SECRET_KEY }}
    AWS_DEFAULT_REGION: auto
    AWS_ENDPOINT_URL: https://${{ secrets.R2_ACCOUNT_ID }}.r2.cloudflarestorage.com
  run: |
    aws s3 cp /tmp/r2-upload/ s3://${{ secrets.R2_BUCKET_NAME }}/${{ github.run_id }}/${{ github.run_attempt }}/scanner-output/ \
      --recursive --exclude "*" --include "*.sarif" --include "*.json"
```

### 2.2 Orchestrator Assembly Changes (`source_identity.py`)
The aggregator job no longer needs to query the GitHub REST API for artifact metadata. Because the R2 bucket structure is strictly partitioned by `${{ github.run_id }}/${{ github.run_attempt }}/`, the aggregator can perform a single, high-speed directory sync.

**New Sync Logic:**
```python
subprocess.run([
    "aws", "s3", "sync", 
    f"s3://{bucket}/{run}/{attempt}/", 
    ".hosted/artifacts/",
    "--endpoint-url", f"https://{account}.r2.cloudflarestorage.com"
])
```

## 3. Data Lifecycle & Cost Management
To ensure this solution remains 100% free under Cloudflare's tier:
- **Ephemeral Storage:** R2 is *only* used for temporary brokering between the parallel jobs and the aggregator job (a lifespan of ~5 minutes).
- **Lifecycle Rule:** An automated Bucket Lifecycle Rule must be configured in the Cloudflare Dashboard to permanently delete all objects in this bucket older than 1 day.
- **Permanent State:** The final, aggregated `unified-findings.json` generated by the normalizer is stored permanently in the main dashboard hosting bucket/KV, entirely independent of this temporary R2 artifact bucket.

## 4. Security & Authentication
The following secrets must be provisioned in the GitHub Repository to authorize the AWS CLI client:
- `R2_ACCESS_KEY`: A scoped Cloudflare API token with Object Read/Write access.
- `R2_SECRET_KEY`: The accompanying secret key.
- `R2_ACCOUNT_ID`: The Cloudflare Account ID.
- `R2_BUCKET_NAME`: The target bucket name (e.g., `code-analysis-artifacts`).
