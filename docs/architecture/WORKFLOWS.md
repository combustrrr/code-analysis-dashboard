# Workflow catalog

Every GitHub Actions workflow in `.github/workflows/`, its trigger, permissions, and role in the analysis pipeline.

## Numbering convention

| Range | Role | Notes |
|---|---|---|
| `01`-`04` | Core scanner groups | Manual dispatch; dispatched together by `08-full-code-analysis.yml` |
| `05`-`10` | Orchestration | Aggregation, full analysis, advisory refresh, discovery |
| `06`-`07` | Validation and fuzzing | Canary validation, API fuzzing |
| `11`-`12` | Generated exact-source | Generated by `generate_source_workflow.py`; do not edit |
| `13`-`15` | Maintenance | Scanner updates, compatibility, tooling rollout |
| `16`-`24` | Standalone scanners | Manual dispatch; continue after maintenance to avoid duplicate prefixes |
| named | Infrastructure | Reconciliation, source dispatch, Pages deployment |

Generated workflows (`11`, `12`, `reusable-source.yml`, `reusable-source-full.yml`) are produced by `scripts/code_analysis/generate_source_workflow.py` and `scripts/code_analysis/generate_reusable_workflows.py`. Regenerate them with those scripts; never edit by hand.

## Core scanner groups (01-04)

| File | Name | Trigger | Permissions | Timeout | Purpose |
|---|---|---|---|---|---|
| `01-code-quality.yml` | Code Quality | `workflow_dispatch` | contents:read, pull-requests:read | 15-30m | Ruff, Pyright, ESLint, TypeScript, SonarQube Cloud |
| `02-security-sast.yml` | Security / SAST | `workflow_dispatch` | contents:read, actions:read | 30m | CodeQL, Semgrep, Bandit |
| `03-dependency-security.yml` | Dependency & Supply Chain Security | `workflow_dispatch` | contents:read | 30m | OSV, Gitleaks, Trivy, Checkov, Snyk, Scorecard, shipping-image security |

All four use read-only repository access (`persist-credentials: false`), accept `scan_sha`/`scan_branch`, and pin checkout to the exact selected commit. Existing artifact-upload steps may still use the repository R2 credentials.

## Safety contract

- Scanner repository access is read-only: `contents: read` and `persist-credentials: false` on every checkout; artifact uploads use only the narrowly scoped credentials required by the workflow.
- No scanner workflow writes issues, pull requests, or commits to the analyzed repository.
- `security-events: write` is not granted to generated source or diagnostic jobs. It is
  present only on the explicitly scoped discovery/reconciliation/native-publication job
  paths that need GitHub security feedback.
- Repository-content write permission appears only in reconciliation/publication jobs that operate on the service repository itself.
- Generated workflows carry no SARIF publication privileges, R2 credentials, or vendor credentials in source-executing jobs.
- Source producer evidence uses GitHub Actions artifacts; R2 is reserved for reconciliation/publication and current-report storage.
